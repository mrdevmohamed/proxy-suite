# 09 — مواصفة Shadowsocks (مرجعية)

> **غير منفذة** في proxy-suite. وموثقة للاكتمال؛ واستخدم خادم Shadowsocks مختصًا
> (مثل shadowsocks-rust) إن احتجتها.

## الفكرة

تشفير موثق بمفتاح مشترك مسبقًا لكل تدفق TCP / حزمة UDP. ولا طبقة هوية beyond
المفتاح — فمن يملك المفتاح يستخدم الخادم. بسيط وسريع ومناسب للاستخدام الشخصي
أحادي القفزة.

## تدفق TCP (شفرات AEAD مثل `aes-256-gcm` و`chacha20-ietf-poly1305`)

```
salt            : بايتات بطول المفتاح (عشوائية لكل اتصال وتُرسل مكشوفة)
sealed[target]  : ‏AEAD ‏(المفتاح الفرعي المشتق من salt والعداد 0) {
                    atyp : بايت (0x01 للـIPv4 | ‏0x03 للنطاق | ‏0x04 للـIPv6 — بترقيم SOCKS)
                    addr : متغير
                    port : بايتان
                  }
sealed[chunks]* : ‏AEAD بعدادات متزايدة {
                    len  : بايتان
                    data : حتى 0x3FFF بايت
                  }
```

اشتقاق المفتاح الفرعي: `HKDF-SHA1(masterKey, salt, "ss-subkey")`.
ويفشل فك التشفير مغلقًا عند أي عبث (لا صفحة بديلة، خلاف Trojan+HTTPS).

## الطرق الشائعة

| الطريقة | طول المفتاح | ملاحظات |
|---------|-------------|----------|
| `aes-256-gcm` | ‏32 بايتًا | مدعومة على نطاق واسع |
| `aes-128-gcm` | ‏16 بايتًا | أسرع وكافية لمعظم الحالات |
| `chacha20-ietf-poly1305` | ‏32 بايتًا | بدون AES-NI استخدم هذه |
| `2022-blake3-*` | ‏16/32 بايتًا | أحدث مع مفتاح UDP منفصل |

تجنب الشفرات التدفقية القديمة (`rc4` و`bf-cfb` و`aes-*-cfb`) — فلا سلامة لها.

## شكل الرابط (SIP002)

```
ss://<base64(method:password)>@<host>:<port>?plugin=<...>#<name>
```

## ‏Shadowsocks مقابل هذا المشروع

|  | ‏Shadowsocks | ‏VLESS/Trojan-WS هنا |
|--|----------------|----------------------|
| الهوية | مفتاح مشترك | ‏UUID / بصمة كلمة مرور |
| البصمة | كتلة AEAD (تُكتشف باختبارات الإنتروبيا) | ‏WS+TLS يمتزج مع الويب |
| ملاءمة CDN | لا | نعم (توجيه بمسار WS) |
| ‏UDP | نعم | لا |

استخدم Shadowsocks للأجهزة الضعيفة / الإعدادات البسيطة؛ واستخدم هذا المشروع عندما
تريد تمويه CDN وعمليات بروكسي عكسي قياسية.
